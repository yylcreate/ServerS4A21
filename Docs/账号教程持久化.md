# A21 账号教程持久化

账号教程集合与角色教程标记、角色奖励相互独立。拍卖行引导使用账号flag8；客户端正常关闭、Esc及完成最后一页都代表该账号已作展示选择，服务端持久化该选择，不在重登后重复自动展示。

`ServerRuntimeBuilder` 显式创建账号教程owner，默认文件 `Data/account-tutorial.db`，可通过 `ACCOUNT_TUTORIAL_DATABASE_PATH` 指定路径。独立基线为 `a21-account-tutorial-v1`，版本1，不占用公共数据库迁移编号。未知基线、未知版本和同版本结构差异均拒绝采用；不携带默认账号或运行数据库。

## A21 协议证据

正常关闭和Finish经客户端 `00ACBA40 → 00ACB860` 发送mode1。`DungeonTutorialHandler` 将该mode保存到账号集合，重复上报幂等，不给角色发奖励。mode0继续使用角色教程流程；未知mode和越界账号标记拒绝。

登录时 `ACCOUNT_TUTORIAL_INFO` 仅发送一份 `u8 count + flags`，位于 `SELECT_CHARACTER` ACK之后、首次 `USERINFO` 之前。客户端 `02F0DC30 → 00ACEA60` 在恢复时先清空16位集合，因此不能发送旧的三份零数据覆盖已保存集合。opcode名称统一引用 `PacketTypesA21.cs`。

## 验证

运行 `--selftest-account-tutorial-database` 验证保存、重开、账号隔离、幂等和未知schema拒绝；`--selftest-a21-tutorial-protocol` 验证mode与登录恢复包；共享进号与副本路径还需串行运行 `--selftest-all`。所有测试均使用离线owner，不启动另一个游戏服务。

原生客户端完成/关闭教程后的重登开拍卖行、每次登录首次退出副本已由人工确认。构建要求0 warning / 0 error；部署前备份独立教程库，回滚服务端二进制不回滚玩家数据。
